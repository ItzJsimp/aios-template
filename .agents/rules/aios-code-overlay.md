# Leonidas Code: shared operating layer

Leonidas Code is the daily workspace. It owns conversations, provider selection,
delegation, approvals and visual tools. The AIOS owns identity, memory, modes,
skills, tasks and standards on disk. Load this layer for every provider.

- Read the resident identity, soul, core and mode router linked by the AIOS
  root instructions before acting. In a project session, read both the project
  brief and this user's AIOS canon. Verify the identity canary in a fresh session;
  an available path or import directive alone does not prove it loaded.
- Select providers and accounts from the running app's live capabilities.
  A subscription is an account entitlement, not a separate workspace. Report
  unavailable providers accurately; never invent a connection or a model limit.
- Use app-owned tools when available. Delegated child work stays attached to
  the current thread; separate top-level conversations require an explicit
  request. Check authorization before spawning agents or spending.
- Keep new UI capabilities inside the {{AIOS_NAME}} app. The Command Center is its
  operations surface. Use the collaborative browser for browser work when
  exposed; inspect status and open it before declaring it unavailable.
- Follow the current provider's tool contract and the AIOS trust contract.
  Claude SDK files, Codex instruction discovery and ACP configuration are
  runtime adapters. They do not require using their old standalone interfaces.
- Treat old Claude Code, Clio and Antigravity UI workflows as historical or
  compatibility-only. Do not route daily work, onboarding or account switching
  through them. Preserve runtime dependencies until verified replacements exist.
- Keep durable state in the AIOS, not only in a provider conversation. Before a
  quota or provider handoff, save verified progress, unfinished gates and a resume
  prompt. Continue in Leonidas Code with the next authorized connected account.
- Read skills from the canonical skills folder. Provider-specific discovery
  folders are generated adapters. Old terminal status-line plugins and slash
  commands are not portable app features; use only integrations verified in
  the running provider.
